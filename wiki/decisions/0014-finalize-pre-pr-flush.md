# ADR 0014: `memoria finalize` is the pre-PR flush

**Problem**: wiki writes were gated on session end ([[concepts/session-capture]]), and memoria is branch-blind — pages land on whatever branch is checked out when the background job fires. The common failure: a feature PR merges while the chat is still open, so the session's wiki pages appear only after the agent closes, on main (protected) or mid-way into the next feature, forcing a separate trailing PR ([[gotchas/auto-apply-rewrites-wiki-mid-session]] is the same blindness from the other side). Raised directly from this failure mode: with the live config's `auto_apply: true` and `wiki_auto_commit` unset (off), a merged PR routinely left its wiki pages sitting dirty in the working tree, attributed to whichever branch happened to be checked out when the background consolidation fired.

**Decision**: an explicit finalize verb, mirroring ai-memory's `finalize-session` ([[research/ai-memory-handling-of-memoria-flaws]] §3). Three pieces:

- **`memoria finalize [<sid>] [--no-apply]`** (finalize.go): stamps `ended_at` + marks the queue entry ended (`finalizeSession` — the same state the session-end hook leaves), then runs `generateProposal` inline. An explicit command applies regardless of `auto_apply` (the [[decisions/0010-wiki-auto-commit-is-opt-in]] reasoning); `--no-apply` keeps the review gate. Guards: refuses to run on an already-processed session, and refuses while the project's background job slot is busy.
- **`memoria_consolidate end_current=true`** (MCP): finalizes the caller's still-open pending session first, then the normal job/poll/apply flow. Guarded so polls are harmless: only a pending digest without `ended_at` is finalized.
- **Pre-PR nudge, two surfaces**: the MCP server's `Instructions` string and the bootstrap AGENTS.md recall block ([[concepts/recall-and-run]]) both now tell the agent to flush with `end_current=true` and commit the wiki to the feature branch before creating a PR. Independently, a successful `gh pr create` captured from a claude-code session with unflushed observations emits PostToolUse `additionalContext` JSON on stdout with the same reminder. Both are additive context only — never a block ([[decisions/0003-never-block-the-agent]]). The hook nudge is deliberately narrow: it skips other clients, failed commands, and sessions with no unflushed observations, and excludes `git push` as spam.

**Why no new machinery**: the chat continuing after finalize is the already-existing incarnation mechanism (`<sid>-2.md`, [[gotchas/implicit-session-end]]), and appends racing the processing window are covered by [[decisions/0009-apply-time-race-detection-via-digest-size]]. The trailing incarnation ("created PR, merged") is small and [[concepts/session-decay]] handles it.

**Rejected for now**: branch stamping at capture and `memoria commit --pr` automation for wiki writes that still land late — add only if trailing writes stay painful with finalize available.

**ai-memory comparison, checked before building**: research into ai-memory's actual behavior (it is installed locally on this machine as the AUR package `ai-memory-bin`, docs at `/usr/share/doc/ai-memory/`) confirmed it has the identical gap at the wiki-compilation layer — pages compile at session-end, PreCompact, or opt-in `AI_MEMORY_CONSOLIDATE_ON_SESSION_END`, all still session-end gated. Its real answer is the same shape memoria already had before this ADR: `memory_write_page` callable any time mid-session, plus `ai-memory finalize-session --agent <agent>` as a manual full close usable without exiting the harness. ai-memory has no branch-change/commit/merge hook either — nothing in it observes "PR merged" and flushes automatically; named workstreams are its manual stand-in for per-branch lines of work. So this ADR isn't closing a gap ai-memory already solved — both tools push the burden onto an explicit, agent-triggered flush.

New workflow: finish feature → `memoria finalize` (or the MCP flush) → commit `wiki/` to the feature branch → PR carries code and wiki together.
