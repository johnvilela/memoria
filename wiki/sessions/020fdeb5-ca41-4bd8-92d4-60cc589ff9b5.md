"The main branch is blocked to commit, i switch to a new branch to work on a feature, we work on a feature and create the PR with no problem but i never run '/exit' or '/new' on the chat. So i approve the PR with the code but without the wiki related to that code, only after i close the ai-agent is when the digest occur and i need to open a new PR to avoid losing the information or pushing the wiki update with a unrelated feature." ## Recon

Extensive reads of memoria's own hook/digest/consolidation/commit code (`hook.go`, `hooks.go`, `digest.go`, `wikigit.go`, `process.go`, `mcp.go`, `commit.go`, `run.go`) plus a discovery: **ai-memory is actually installed on this machine**, not just researched via GitHub — the AUR package `ai-memory-bin 1.38.0`, a Rust server daemon (systemd unit, SQLite+FTS5) with docs at `/usr/share/doc/ai-memory/README.md`/`install.md`, hook bundles for 15+ harnesses at `/usr/share/ai-memory/hooks/`, and config at `/etc/ai-memory/config.toml` / `~/.config/ai-memory/config.toml`.

Two background subagents ran in parallel:

- **ai-memory's handling**: confirmed it has the *same* gap at the wiki-compilation layer — pages compile only at session-end, PreCompact, or the opt-in `AI_MEMORY_CONSOLIDATE_ON_SESSION_END`. Its real answer is `memory_write_page` (callable any time mid-session, immediate git-versioned page) plus `ai-memory finalize-session --agent <agent>` (a manual full close, built for harnesses lacking a true SessionEnd but usable as a general mid-session flush). Git/branch awareness there is shallow too: repo+worktree fingerprinting, git checkpoints in handoff packets, and page-level checkpoints/restore — but **no branch-change, commit, or merge hook**; named workstreams are the manual stand-in for per-branch lines of work.
- **memoria's own trigger chain**: traced the exact path — session-end hook spawns full consolidation only when `auto_apply` is on; `memoria_digest`/`memoria digest <sid>` is the only mid-session, agent-initiated wiki write; the cron timer (`process --all`, 8×/day, `cron_apply: true` in the live config) sweeps on a clock. Confirmed **zero git branch awareness anywhere in memoria's code** (`grep -rni branch cmd/*.go` hit only two unrelated test comments) — `wikigit.go`'s `commitWiki`/`commitWikiGit` never check which branch is checked out, and `gitCheckpoint` (run.go) only captures the HEAD subject line, not a branch name. Live config confirmed: `auto_apply: true`, `wiki_auto_commit` absent (off). No config knob exists for "digest at PR time" or "hold the wiki write until X." The recon also caught, live in the working tree, a real instance of [[gotchas/auto-apply-rewrites-wiki-mid-session]]: `wiki/concepts/self-update-command.md` and `wiki/sessions/075393cf-....md` were already dirty *before this session started* — auto-apply output from the previous session's background consolidation, confirmed by matching mtimes against `status.yaml`.

Both subagents converged on the same conclusion: neither tool solves this automatically. The fix has to be an explicit, agent-triggered flush.

## Implementation

On branch `feat/finalize-session`:

- New `finalize.go`: `memoria finalize [<sid>] [--no-apply]` — stamps `ended_at`, marks the queue entry ended, runs consolidation inline, applies regardless of `auto_apply`, refuses an already-processed session or a busy job slot.
- `mcp.go`: `memoria_consolidate` gained `end_current` — finalizes the caller's still-open session first, idempotent on polls (only touches a pending digest without `ended_at`).
- Two pre-PR nudges: the MCP server `Instructions` string and the bootstrap AGENTS.md block both gained a line telling the agent to flush with `end_current=true` and commit the wiki before opening a PR; a separate PostToolUse `additionalContext` hook fires after a successful `gh pr create` from a claude-code session with unflushed observations, skipping other clients, failed commands, sessions with no unflushed observations, and `git push` (excluded as spam).
- `cmd/finalize_test.go` added; existing test call sites (`hook_test.go`, `queue_test.go`, `mcp_test.go`) updated for the new function signatures. Full suite green (`go test ./...`), `gofmt` clean.
- README.md and AGENTS.md updated: new `finalize` command row, `memoria_consolidate`'s `end_current` documented, the pending-queue and hook-flow prose updated to mention the flush and the PR nudge.
- Version bumped to **0.14.0** (minor, per the versioning convention for a new feature).
- `wiki/decisions/0014-finalize-pre-pr-flush.md` written **mid-session via `memoria_write_page`**, specifically so the decision page would ride the same PR — the first real dogfood of the workflow it documents.
