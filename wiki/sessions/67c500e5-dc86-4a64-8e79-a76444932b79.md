# Session: memoria_recall shipped — "what did we do?" answers without writing

**2026-07-29 23:03–23:17 · project memoria · claude-code · commit `d6edeea`**

The bug report, from dogfooding: the user simulated stopping late at night and resuming under a different agent — reopened a claude-code session in codex and asked what had been done. Instead of just answering, codex **created a new wiki page** (the stray `wiki/sessions/019fb0c0-*.md` from the recall dogfood in [[sessions/019fb0c0-23aa-7583-9035-ad2d71dd4ac6]], where that page's appearance left no trace in capture). In the user's words: it "should just ask me based on the session information and not write something".

## Root cause (Explore recon)

The tool surface invited the write:

- The only recall-shaped MCP tool was `memoria_digest`, and it had no read-only mode: every successful call LLM-compiles the observation log and unconditionally overwrites `wiki/sessions/<sid>.md` (`digestForeground` in digest.go — write, then status, then notify).
- The one non-mutating tool, `memoria_search`, only greps the curated wiki (content inlined only at ≤3 hits) — it cannot see raw digests, `.memoria/sessions.md`, or the pending/processed transcripts.
- The server sets no MCP `instructions`; the AGENTS.md block said "prefer the memoria MCP tools" with zero routing; hooks inject nothing back into sessions (no `additionalContext`/`hookSpecificOutput`/`systemMessage` anywhere in the Go tree).
- The richest read-only reconstruction in the codebase — `buildHandoff`'s packet — was reachable only as a `memoria run` launch mechanism, while all its ingredients (`readSessions`, `findDigest`, `digestChain`, `digestEvents`) were already pure functions.

## Fix

The Plan agent's shape held — smallest diff, reuse `buildHandoff`:

- `buildHandoff` gained a `resume bool` (run.go): `true` keeps the resume framing unchanged; `false` renders recall framing — "Read-only record of a past coding session … do not re-run anything", footer keeps the last-state lead but drops "continue the work".
- New **`memoria_recall`** MCP tool (mcp.go): resolves the session via the newly extracted `resolveSession` helper (shared with `memoria_digest`; defaults to the newest session), returns the packet. No LLM, no job machinery, no writes.
- `memoria_digest`'s description now states it WRITES/overwrites the page and routes recall questions to `memoria_recall`.
- The AGENTS.md template (bootstrap.go) gained a routing sentence; the repo's block was regenerated via `memoria bootstrap`. README tool table updated.
- New `TestMCPRecall`; `go build` + full test suite green.

Smoke test over raw stdio JSON-RPC (initialize / initialized / tools/call piped into `go run ./cmd/memoria mcp`): `memoria_recall {}` returned this very session's record, and a saved `ls -l` listing of `wiki/sessions/` diffed clean afterwards — nothing written.
