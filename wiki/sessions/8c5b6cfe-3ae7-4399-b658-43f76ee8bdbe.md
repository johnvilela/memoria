# Session: memoria search made global-aware and headless — PR #7

**2026-08-27 13:10–14:27 · project memoria · claude-code · branch `fix/search-global-scope` · title `fix-cli-search-global-mode`**

Bug report, with a stated real-world motivation: a second machine, driven by "chatgpt work/claude cowork" as a personal-assistant-style controller with no project context of its own, needs a searchable long-term memory — but `memoria search` from an unregistered folder with `global: true` still hard-errored "not inside a tracked project". The invitation to ask clarifying questions went unanswered in the digest; the session went straight into deep recon instead.

## Root cause

An Explore subagent mapped every workspace-resolution call site in the codebase. `resolveProject` (config.go) is the shared helper: try `matchProject` (longest registered-path prefix), and only when that fails, fall back to the `_global` pseudo-project if `cfg.Global` is set. A prior fix (commit `1e87f13`, referenced in the codebase as "#6") had wired this fallback into `mcpProject` (used by all seven MCP tools) and `runDigest`, but **`runSearch` still called raw `matchProject` directly** (search.go:36) and hard-errored instead of falling back — the literal bug reported. The recon named three more untouched bypassers with the identical gap — `runCommit`, `runRun`, `runSeedForeground` — all deliberately left project-scoped per [[concepts/global-capture-mode]], so only `search` was in scope for this fix.

The recon also drew a distinction worth keeping: "global workspace" (memoria's existing meaning — one more workspace selected when cwd matches no registered project) versus "search everything" (a union of the global wiki with the current project's, or all projects') — the second is a genuinely different feature that nothing in memoria implements today, and was explicitly not what this session built.

## Fix

- `mcpProject` renamed to `resolveWorkspace` (mcp.go, via `sed`) since it is no longer MCP-only; `runSearch` (search.go) now calls it instead of raw `matchProject`, so search falls back to the global wiki from an unregistered folder exactly like the MCP tools already did.
- **Headless mode**: without a TTY, multiple matches now print the sorted list of match paths (one per line, exit 0) instead of erroring or requiring the interactive picker; a single match still prints the full page; no matches still exits 1. TTY behavior (the `selectOption` picker) is unchanged.
- TDD: `search_test.go` was edited and run to confirm the new expectations failed first, then the implementation was added to make them pass.
- Docs updated: AGENTS.md's search row, and `wiki/concepts/global-capture-mode.md` — moving `search` from the "left project-scoped on purpose" list to the global-aware one.
- Version bumped 0.10.1 → 0.10.2 in `cmd/memoria/main.go`.

## Verification

Full suite (`scripts/test.sh`) green. End-to-end smoke test against a real built binary: a fake `XDG_CONFIG_HOME` with `global: true` and two wiki pages (a dentist reminder, a groceries reminder) under the global root; run from a separate unregistered directory, `memoria search remember` (non-TTY, piped) listed both pages' paths, and `memoria search dentist` (single hit) printed the full page.
