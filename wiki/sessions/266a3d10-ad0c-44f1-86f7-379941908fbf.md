## What shipped

`memoria bootstrap --global [--global-path <folder>]`: sessions in unregistered folders are now captured too, routed to a `_global` pseudo-project. Registered projects still win via the existing longest-prefix `matchProject`; `_global` is a fallback. Default root is `~/.config/memoria` — the wiki folder there gets its own `git init` plus forced auto-commit, but the config directory itself is never turned into a repo (it can hold `gemini_api_key`, kept 0600). `--global-path <folder>` moves the root elsewhere; memoria never touches git in that folder — it is the user's own repo to manage.

Global digests record real source-folder identity via the previously-unread `project:`/`project_root:` frontmatter keys (nothing is ever written into the source folder itself). The global wiki mixes shared root categories (concepts/, decisions/, …) with per-source-folder namespaces (`<folder>/concepts/...`), taught to the LLM via a Go-appended prompt addendum and enforced by a new `global bool` parameter on `validPagePath`/`validatePages`.

Follow-up in the same session: `memoria setup --global[=false]` and `setup --global-path <folder>` to enable, disable, or move the root without going through bootstrap directly — disabling keeps `global_path` stored so a later re-enable finds the same root. `--global=false --global-path X` together is rejected.

Mid-session rename: at explicit user request, `--path` was renamed to `--global-path` on both `bootstrap` and `setup` (sed across main.go, setup.go, bootstrap.go, help.go, their tests, and AGENTS.md) — the old `--path` now errors as an unknown flag.

## Implementation shape

Per the Plan agent's design: `resolveProject` (config.go) tries `matchProject` first, falls back to the `_global` pseudo-project when `cfg.Global` is set. `globalCommitCfg` flips `WikiAutoCommit` on a **copy** of the config at three dispatch points (`runProcess`, `processAll`, `runLint`) rather than threading the config path through `commitWiki` — avoiding the macOS `XDG_CONFIG_HOME`/`os.UserConfigDir()` test trap already noted in `init_test.go`. Global-aware commands: `captureHook`, `process` (including `--all`, so the cron sweeps it), `lint`. Deliberately left project-scoped: `search`, `run`, `mcp`, `commit`, `digest`.

A real bug was caught by the Plan agent before coding: `applyProposal` only archives digests under the resolved project's path, so changing `--global-path` would leave old-root queue entries stuck re-consolidating forever — fixed by warning at bootstrap/setup time when pending `_global` entries still reference the old root. A second, similar bug was caught by this session's own smoke test: the root-change warning initially fired even for entries already under the *new* root — fixed to warn only about entries genuinely stranded outside it.
