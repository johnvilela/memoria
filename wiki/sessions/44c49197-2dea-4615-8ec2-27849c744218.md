## Part 1: macOS PATH issue

A friend tested memoria on macOS post-install and got `zsh: command not found: memoria` in a new shell.

**Root cause**: `scripts/install.sh` puts the binary in `~/.local/bin`, which macOS zsh does not have on PATH by default. The script only warns ("note: $BIN_DIR is not on your PATH"), never fixes it. Init/bootstrap kept working because hooks and MCP record the absolute binary path; only bare `memoria` in a new shell fails.

**Workaround**: append `export PATH="$HOME/.local/bin:$PATH"` to `~/.zshrc` and re-exec.

**Planned improvement**: install.sh should ask the user where they want the binary (install dir / PATH) and write the PATH export to the right shell rc (`~/.zshrc` on macOS, `~/.bashrc` on Linux). Captured in [[wiki/to-do/install-script-path.md]].

## Part 2: wiki validation redesign

### The gap

Screenshot analysis of a consolidation failure revealed an asymmetry in how memoria treats the wiki:

- **`readWiki`** walks the entire wiki root and reads every `.md` file at any depth — including `research/`, `to-do/`, and any other custom top-level folder.
- **`validPagePath`** has a hardcoded whitelist: only `index.md` + five native categories (`concepts/`, `decisions/`, `gotchas/`, `rules/`, `sessions/`).
- **Consequence**: the LLM sees custom folders in the wiki context (they're in `readWiki`), but cannot write, fix, or delete pages there (validPagePath rejects them). When a proposal touched an existing `research/` page, `validatePages` rejected the **whole batch** with an all-or-nothing error, discarding minutes of LLM work.

### Solution: open folders, keep reservations

Allow user-created top-level folders in the wiki while reserving a small set (trash/, _global/, dot-prefixed).

**Implementation** (full feature, all tests green):

- **`wikiDirs` helper**: lists the wiki root's top-level directories via `os.ReadDir`; missing root → empty map.
- **`validPagePath` updated**: accepts `index.md` + native five (always valid, even before the folder exists) + any existing custom folder. Reserved: `trash/`, `_global/`, dot-prefixed paths.
- **Drop-and-warn pattern**: `validatePages` and `validateLintFix` return `(valid []wikiPage, dropped []string)` instead of a hard error. Each invalid page produces a human-readable reason (e.g., `page "secrets/x.md" dropped: path outside the wiki structure`). Warnings print to stdout and `memoria.log`; the batch fails only when zero valid pages remain. This replaces all-or-nothing rejection.
- **Lint deletes move to trash**: extracted `trashPage` helper (collision-suffix with `-2`, `-3`, …); `lintApply` delete now moves to `trash/` with a `deleted` tag instead of `os.Remove`, matching `memoria_delete_page` behavior.
- **Prompts taught the policy**: 
  - `seed-prompt.md`: added "These are the only valid top-level folders when seeding."
  - `wiki-prompt.md`: added "The category folders are suggestions — a top-level folder that already exists is also valid when it fits better. Never invent new top-level folders."
  - `lintFixPrompt`: clarified delete action moves to trash.
  - `jsonContract` and mcp jsonschema tag updated.
- **Bootstrap warns on reserved folders**: if the wiki contains `_global/` at bootstrap time, a warning is printed.

### Outcome

The wiki is now extensible. A user can create `research/`, `to-do/`, `docs/`, or any other top-level folder; future sessions (via LLM consolidation) can write, fix, and delete pages there. The native five remain the suggested defaults, but are no longer the only valid targets. Invalid paths skip with a warning instead of failing the entire proposal.

Tests: extended `TestValidPagePath`, new `TestWikiDirs`, `TestProcessDropsInvalidPagesKeepsRest`, `TestProcessCustomFolderTarget`, `TestSeedWikiDropsInvalidKeepsRest`, `TestLintApplyDropsBadFixKeepsRest`; updated `TestMCPWritePage` and `TestLintApply`. Full suite green via `go vet` + `go test -race`.
