# Session: processor JSON repair shipped — `6f653b9`

**2026-08-05 23:04–23:41 · project memoria · claude-code · commit `6f653b9`**

## Part 1: diagnosis, no fix yet

Bug report: in the sibling project **kakei**, starting a new session triggered auto-consolidation on the previous session's end, which crashed and wrote nothing to the wiki: `processor returned invalid JSON: invalid character 'f' after object key:value pair`. Explicit constraint: "Do not fix anything yet."

Investigation (`memoria status`, `~/.config/memoria/memoria.log`, `pending.yaml`, kakei's own digest) found: the `claude-code` processor had no `processor_model` set, so it ran on the then-default **haiku**. The consolidation JSON contract crams whole markdown page bodies into a single JSON string — every `"` in a body must come out as `\"`. Re-running kakei's exact prompt through haiku, read-only, reproduced the failure shape: 37 escaped quotes in one page, several dropped-backslash cases matching kakei's own content (`\"feat`, `\"flag`, `\"force`...). Dropping a backslash before an escaped quote closes the JSON string early, so the parser then sees the next literal word (`feat`) where it expects `,` or `}` — exactly the reported error. This was inference, not the literal failing bytes, since the processor discards its raw output on parse failure.

State check: nothing was lost — `pending.yaml` still held the session with `ended: true`, its digest stayed in `pending/`, and an `error` status doesn't block retry (`processAll` only skips a job already `running`), so the next cron firing or next kakei session-end would retry it.

Structural gaps named at the end of Part 1:
1. Raw processor output is discarded on parse failure, including the JSON offset — nothing to inspect post-mortem.
2. No retry — one bad character kills the whole batch until an unrelated trigger fires, hours later.
3. All-or-nothing batch — even a 5-page proposal dies on one malformed page.
4. The transport itself is fragile — asking the cheapest model to perfectly escape thousands of characters of markdown inside a JSON string value.
5. The same parse-and-fail code was duplicated across `digest.go`, `lint.go`, `seed.go` and `process.go` — one failure mode, four places to fix.

## Part 2: the fix — "less AI interaction, more deterministic"

Follow-up instruction: fix it, add a test suite, and prefer deterministic solutions over AI round-trips wherever possible.

**New `cmd/memoria/jsonout.go`** — one shared parser now used by all five processor call sites (`process`, `digest`, `lint` report, `lint` fix, `seed`):

```
extract → unmarshal ──fail──→ repairJSON() → unmarshal ──fail──→ dump raw + offset window
```

`repairJSON` is a plain byte scanner, no AI call: a `"` inside a string closes it only when the next non-space byte is `,` `:` `}` `]` or EOF — anything else means a dropped backslash, so it gets escaped. Raw control characters get the same treatment. On genuinely valid JSON that condition can't occur, so the function is the identity on valid input (verified against 9 shapes). Known ceiling, documented and tested: a case like `say "hi", ok` is truly ambiguous and still fails loudly rather than silently corrupting a page.

A repaired run isn't silent: it's flagged in `memoria.log`, in stdout, and in the `memoria status` detail ("— output repaired"), with the raw output kept on disk so a bad repair can be checked.

**`jsonout_test.go`**: the load-bearing case marshals a quote-heavy body correctly, then drops one backslash at a time and asserts all 8 resulting variants round-trip byte-identical after repair, plus dump-file, offset-context, and one end-to-end guard per call site. Writing it caught a real pre-existing bug: an `err` shadowed inside an `if`/`else` that was writing `# <nil>` into the dump file instead of the actual error.

**Also in the same pass**: the claude processor's default model moved from `haiku` to `sonnet` (`processor_model: haiku` in config still selects the old default explicitly) — see [[concepts/processor-models-and-effort]]. One escaping-instruction line was added to all four prompt contracts (digest, seed, lint, wiki/process). `AGENTS.md` updated.

**Verification**: `scripts/test.sh` (`go vet` + `go test -race`) green, 17 new passing cases. kakei's stuck session was replayed for real against the rebuilt binary: `error` → `done`, 5 pages applied, digest moved to `processed/`, queue entry consumed — sonnet parsed clean on the first try, no repair needed.

**Left open**: `~/.local/bin/memoria` — the binary actually invoked by installed hooks and the cron timer — was still the Aug 1 build at session end; `scripts/dev.sh` installs the fixed one.
