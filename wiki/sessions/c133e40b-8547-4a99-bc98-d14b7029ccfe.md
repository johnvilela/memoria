## Part 1: codex refuses untrusted directories — root cause and fix

Bug report from the user (with screenshot): memoria was breaking under codex — the error "Not inside a trusted directory" appeared when running `memoria bootstrap` to seed the wiki.

Recon (Explore agent) mapped the issue: the processor's `runProcessorCmd` (processor.go:44-58) unconditionally sets `cmd.Dir = os.TempDir()` as a recursion guard (so nested agent sessions don't capture back into memoria). This works fine for `claude -p` — Claude tolerates untrusted dirs. But `codex exec` refuses to run anywhere outside a git repo or a hardcoded trusted path list (codex's security model). The project dir was never used by the subprocess (the prompt includes all needed content via stdin from `buildSeedPrompt`'s git shell-outs), so it was safe to change.

**Fix** (`processor.go`): thread the project directory through `invokeProcessor` and `runProcessorCmd`, add `hasGitDir(dir)` check — if the project root has `.git`, codex runs there (codex trusts git repos natively); otherwise temp dir + `--skip-git-repo-check` flag. Claude unchanged (always temp dir; `MEMORIA_NO_CAPTURE=1` already guards recursion). Applied to all LLM call sites (seed, digest, process, lint×2) — codex was broken in all of them, not just bootstrap.

Two new tests pin the codex argv and cwd; full suite green. Documented in AGENTS.md. Binary rebuilt.

## Part 2: cheaper models by default — processor model and effort config

Second improvement: wiki work (seed, digest, consolidation, lint) is text digestion — no need for expensive reasoning. Defaults now: claude → `claude -p --model haiku`; codex → `codex exec -m gpt-5.4.mini -c model_reasoning_effort=high`. Both override-able in config.yaml:

```yaml
processor_model: sonnet      # or any claude/codex model name
processor_effort: medium      # codex only; claude has no effort flag
```

**Implementation**: two new config fields (`ProcessorModel`, `ProcessorEffort`); processor.go updated to build the argv with defaults; tests pin both defaults and overrides for both CLIs. Applies to all LLM tasks (seed, digest, process, lint). Gemini untouched (hardcoded gemini-2.5-flash REST call). Binary rebuilt.

## Part 3: wiki auto-commit — changes committed when applied

Third improvement: when memoria applies changes to the wiki (proposals, lint fixes, seed, session pages), automatically commit them if the wiki is inside a git repo. This keeps wiki changes versioned without asking the user to remember a commit step.

**New file** `wikigit.go`: `commitWiki(cfg, wikiRoot, action, summary, fileCount, projName)` stages the wiki folder and commits it with a pathspec commit (so user's own staged non-wiki files stay untouched). Message template from `wiki_commit_message` config field (default `docs(wiki): {action} — {summary}`), allowing custom patterns:

```yaml
wiki_commit_message: "wiki: {action} [{count}] {project}"
```

Placeholders: `{action}` (apply/fix/seed/digest), `{summary}` (short reason), `{count}` (files), `{project}` (name). Skips silently when wiki isn't in a git repo; git failures log and never break the apply. No push.

**Triggers**: `applyProposal` (manual/auto-apply/cron/MCP), `lintApply`, `seedWiki`, `digestForeground`. MCP `write_page`/`delete_page` deliberately excluded — those ride in the user's own commit and get swept into the next auto-commit anyway.

Four new tests cover default + custom message, staged-file isolation, non-git no-op. Full suite + vet pass. README and AGENTS.md updated. Binary rebuilt.
