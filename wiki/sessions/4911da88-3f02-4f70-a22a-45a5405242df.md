## The work

User requirement: auto-commit of wiki pages (added in [[decisions/0006-wiki-auto-commit-on-apply]]) should be opt-in, not unconditional. It should be set via `init`/`setup` with a flag or TUI prompt, and absent from the config means off — existing installs stop committing. A new `memoria commit` command provides the manual path: stages and commits wiki changes (including untracked pages) with the same message pattern.

## Three pre-existing fixes discovered

Recon uncovered three substantive bugs already in the tree, uncommitted:

### 1. Session page incarnation suffix leaked into wiki paths

Digest filenames include incarnation numbers (`sessions/<sid>-2.md`, `-3.md`, etc.) as internal bookkeeping. Processors wrote pages using the full digest filename. Readers (`memoria run`, `memoria_recall`) hardcoded `sessions/<sid>.md` (bare id), so suffixed pages were invisible to the handoff system. Affected: a 60KB session from the motolink project that consolidated to `wiki/sessions/c589857b-...-2.md` but was never found by run.

**Fix** (`process.go`): `canonicalizeSessionPaths` scans the batch for `sessions/<sid>-<digit>+.md` patterns, reads each digest's `session_id` frontmatter, and rewrites the path to the bare id. Orphan pages (naming no session in the batch) are dropped; collisions are reported.

### 2. Empty digests poisoned the queue

A session starting and exiting immediately (e.g., `@session-start source: resume` + `@session-end reason: prompt_input_exit` with zero events) produced a valid but valueless digest. The LLM correctly returned `{"pages":[]}`, treated as a hard failure. The queue entry was never removed, re-failing on every hook and cron cycle. Two real examples from motolink lasted 3 hours each.

**Fix** (`process.go`): `digestHasContent` checks if a digest has any event line beyond the bookends. `retireEmptyDigest` archives empty ones to `processed/` and removes the queue entry. Wired into `collectEnded` — the single bottleneck all three LLM callers route through. One guard point, three callers, no duplication.

### 3. Digests grew during processing, appended events were lost

The window between "digest read for the LLM prompt" and "digest archived after LLM completes" (1–10 minutes) allowed the still-running agent to append new events. Those events were never in the prompt, then got archived unread. Bounded loss (next events self-heal going forward), but silent and automatic under `auto_apply`.

**Fix** (`process.go`): `proposal.Sizes` stamps digest byte-length when the prompt was built. `digestConsumed` checks if byte-length matches at apply time; a digest that grew is left queued instead of archived, re-consolidated on the next pass with the full content.

### 4. Continuation digests overwrote shorter originals

When a reopen incarnation (`continues_from` present) consolidates and writes to `wiki/sessions/<sid>.md`, it replaced the original wholesale, losing sections. The prompt is asked to extend existing pages, but that signal wasn't carried explicitly.

**Fix** (`process.go`): `buildPrompt` emits a named continuation marker when a digest continues and the session already has a wiki page, telling the LLM to extend rather than re-summarize. `prompts/wiki-prompt.md` now states the unit rule: "every page emitted replaces the whole page at that path; it is not a patch."

## The opt-in gate and new command

**Config** (`config.go`): new field `WikiAutoCommit bool` (default zero = off). Existing installs preserve their behavior by default only if they explicitly set it; upgrade without the flag = no auto-commit.

**Implementation**:
- `commitWiki` (wikigit.go) returns early if `cfg.WikiAutoCommit` is false, so all four call sites (`process --apply`, `lint --apply`, seed, `digest`) stay untouched
- Split `wikigit.go` into three functions: `commitWiki` (gate), `wikiCommitMessage` (template), `commitWikiGit` (git ops, now returns errors)
- New `commit.go` command: `memoria commit [-m subject]` stages and commits wiki changes, ignoring the config gate (explicit command always commits)
- `wikiChanges` lists modified + untracked pages with repo-relative prefix stripped
- Pathspec commit (`git add -A .` with cwd = wiki root) keeps user's staged non-wiki files untouched

**Config knob** (wiki_commit_message):
```yaml
wiki_auto_commit: true    # opt-in flag
wiki_commit_message: "wiki: {action} [{count}] {project}"  # optional override
```

Placeholders: `{action}` (apply/fix/seed/digest/update), `{summary}` (short reason), `{count}` (file count), `{project}` (name).

**Set via**:
- `memoria init --auto-commit` or TUI prompt during setup
- `memoria setup --auto-commit` to add to existing install
- Hand-edit `~/.config/memoria/config.yaml`

- Commit with modified + untracked pages → pathspec stages only wiki
