**2026-07-31 22:05–22:23 · project memoria · claude-code · commit `5a01725` + tag `v0.7.0`**

First release of memoria. Decision and implementation in one session.

## Version choice

User asked what version memoria should be, given no prior tags and ~49 commits. Claude analyzed the feature history in six eras (core CLI, digest pipeline, lint, ops, run, MCP, multirepo/custom-folders) and suggested **0.7.0** as a candidate, leaving 0.6.x for retro-mapping the feature clusters. User accepted 0.7.0 and requested immediate release.

## Implementation

- Added `const version = "0.7.0"` to `cmd/memoria/main.go` — single source of truth.
- Added `memoria version` subcommand (also `--version`, `-v` flags) to print the version.
- Synced `cmd/memoria/mcp.go` handshake from hardcoded `"0.1"` to use the `version` const.
- Updated `cmd/memoria/help.go` to include the version subcommand in the help text.
- Tested: `go build ./...`, `go test ./cmd/memoria/`, `memoria version` verified output.
- Committed as `5a01725` (`feat(cmd): add version subcommand and sync mcp handshake to 0.7.0`).
- Tagged `v0.7.0` and pushed both commit and tag to origin.

## Release ritual documented

Wrote [[skills/release-ritual.md]] with the six-step process: pick version, bump const, build/test/verify, one commit, tag, push. Includes a gotcha: const and tag must move together — a tag without the const bump makes `memoria version` lie.

**Pattern**: semver pre-1.0 uses minor bumps per feature batch, patch per fix-only release. Next release: 0.8.0 when the next feature cluster lands (e.g., if custom-folder wiki extensibility stabilizes, or new agents join the multi-agent registry).
