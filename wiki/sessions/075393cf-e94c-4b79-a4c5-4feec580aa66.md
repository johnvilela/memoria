## Follow-up (resumed 22:23–23:31): does `memoria update` also update the MCP server?

Question asked after resuming the session: does `memoria update` also update the installed MCP server?

Answer given, grounded in reading `cmd/init.go` and `cmd/update.go`: yes — the MCP server isn't a separate install, it's the same `memoria` binary running in `mcp` mode. `init` registers the MCP server (and hooks) in the agent's config using the absolute path from `os.Executable()` (`cmd/init.go:444`). `update` replaces exactly that file: it resolves the path through symlinks (`cmd/update.go:122`) and atomically renames the downloaded release binary over it (`cmd/update.go:201`). So after `memoria update`, the very next `memoria mcp` launch runs the new version — nothing to re-register.

Caveat: an MCP server that's *already running* (spawned by an agent session that's still open) keeps the old code in memory until that session restarts, since agents only re-read tool descriptions and server instructions at the `initialize` handshake. Any new session started after the update gets the updated server automatically.
