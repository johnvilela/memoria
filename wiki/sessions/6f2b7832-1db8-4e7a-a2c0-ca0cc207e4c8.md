## Implementation

New `cmd/memoria/update.go` (`runUpdate`), TDD — `update_test.go` written and confirmed red first:

- Fetches `https://api.github.com/repos/johnvilela/memoria/releases/latest` (a package var, `latestReleaseURL`, for test stubbing).
- Compares versions **numerically** (`parseVer` parses `x.y.z` into an int triple), not by string inequality — a dev build ahead of the last release reports "nothing to do" instead of offering a downgrade.
- Prints the changelog and confirms via the same `selectOption` picker pattern as `seed.go`; `-y` skips the prompt; without a TTY and without `-y` it prints the info plus a `memoria update -y` hint and exits 0.
- Downloads the `memoria_<GOOS>_<GOARCH>` asset and `checksums.txt`, verifies the binary's sha256, and only then atomically replaces the running binary: `os.Executable()` (behind a stubbable `executable` var) resolved through `filepath.EvalSymlinks`, written to a temp file in the same directory, `chmod 0755`, then renamed over the running binary. Any failure before the final rename leaves the installed binary untouched.
- 10 new tests against an `httptest` server with `latestReleaseURL`/`isTTY`/`selectOption`/`executable` stubbed — covering up-to-date, local-newer, non-TTY hint, decline, successful install, checksum mismatch, missing platform asset, and symlink-target resolution.

`scripts/install.sh` rewritten: the standalone path now downloads the checksum-verified release binary for the detected OS/arch instead of `go install ...@latest` — Go is only needed for in-repo/dev builds now, resolving the `ponytail:` TODO recon found.

Version bumped to **0.9.0**; help screen, README, and AGENTS.md command tables updated to list `update [-y]`.

## Follow-up: why is the binary 15 MB, and trimming it

The user asked why the binary was 15 MB. Investigation (`go tool nm -size`) broke it down: roughly 2 MB baseline Go runtime/stdlib, ~1.5 MB crypto+net (the TLS stack, needed for HTTPS calls to the Gemini and now GitHub APIs), the MCP SDK + jsonschema-go, the full charm TUI stack (bubbletea/lipgloss/bubbles plus Unicode segmentation tables), encoding/json, yaml.v3, regexp — and about 5 MB of symbol table + DWARF debug info, which `-ldflags="-s -w"` drops for free: Go keeps a separate, always-present `pclntab` table the runtime itself needs, so panic stack traces still show real function names and line numbers even fully stripped.

Fix: added `-ldflags="-s -w"` to `scripts/build.sh`'s release path only (the local/dev build path is untouched, so `delve` still works locally). Verified all four cross-compile targets rebuild at roughly 9-11 MB, down from ~15 MB. Committed separately as `build: strip symbol table and DWARF from release binaries`, pushed to the same branch.
