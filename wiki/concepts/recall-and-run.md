# Recall: bootstrap, AGENTS.md block, run, search

Capture is opt-in per project: `memoria bootstrap`, run inside the project, registers the folder as tracked (commit f5d66ee), gitignores `.memoria/`, creates the wiki folder (`--wiki <name>` to rename), and offers to seed the wiki from git history (`--background` detaches; seed prompt at `cmd/prompts/seed-prompt.md`). Wiki seeding originally lived in `init` and was moved to `bootstrap` (commit 37a7a77).

**Recall block**: bootstrap writes a marker block into the project's `AGENTS.md` telling agents where the memory lives and to prefer the MCP tools, plus a `CLAUDE.md` shim; the block is repaired on re-run (commit 0eca8b2, README §Commands). Since commit `d6edeea` ([[sessions/67c500e5-dc86-4a64-8e79-a76444932b79]]) the block also routes tool choice: to recall what a past session did, call `memoria_recall` (read-only); `memoria_digest` writes the session's wiki page and is for when the user asks to save it. Re-running `memoria bootstrap` regenerates the block in place. This is how a fresh agent session learns the wiki exists — see [[concepts/mcp-server]].

**`memoria run <agent-binary>`** (commit 0643004) launches any agent on PATH inside the project, continuing a previous session: same harness → native resume (`claude --resume`, `codex resume`); different harness → a self-contained **handoff packet** (commit ad5d206, below). Session selection, reworked in [[sessions/4f8bca2c-fb25-45fb-a0ee-cc7e9a42e5d3]] and committed as `0d9d968` ([[sessions/cf99acf5-2ee6-4118-90b5-1a2964766475]]): `--new` forces a fresh session; `--session <id|name>` matches by sid prefix or name substring, case-insensitive (multiple hits open a picker on a TTY); with no session given, run shows a picker of "New session" plus the last 5 sessions, with warnings on digest-less ones. The rework retired the `--last-session` flag and the earlier yes/no "continue last session?" default prompt — the picker covers both.

**Cross-harness handoff packet** (commit ad5d206, [[sessions/e915be64-f9af-4a50-a147-8a4831159754]]): `buildHandoff` in `run.go` replaced the earlier one-sentence "read the session digest at <path>" prompt, which cross-harness agents misread as a fresh task instead of a resume. The packet is deterministic (no LLM call) and goes as the agent's single initial argv prompt: resume framing, source-harness provenance from the digest's `client:`, a git checkpoint (`gitCheckpoint`, a stub-able var; omitted outside a repo), digest event history following the `continues_from` chain oldest-first (`digestChain`, cycle-safe, depth 5; `digestEvents` collapses lines and drops consecutive duplicates), the wiki `sessions/<sid>.md` page when present (via `wikiRootFor` in config.go, which respects the `wiki:` config override), and a footer led by the session's last main `@stop` (see the ask-first rework below). Budgets keep it argv-safe: 24k-byte packet, 2k-rune event lines, 6k wiki page — oldest events drop first with a note, and the digest paths are always named so the agent can read the full log. Since commit `d6edeea` ([[sessions/67c500e5-dc86-4a64-8e79-a76444932b79]]), `buildHandoff` takes a `resume` bool: `memoria run` passes true, while the MCP `memoria_recall` tool reuses the same builder with `resume=false` — the header becomes a read-only "Session record" ("use it to answer questions … do not re-run anything") and the footer keeps the lead but drops the instruction to act ([[concepts/mcp-server]]). The design came out of the ai-memory research ([[concepts/handoff-vs-ai-memory]]). Dogfooded in both directions the same night: claude-code → codex ([[sessions/019fb0a0-48d0-71f1-954f-7036553b2133]]) and codex → claude-code ([[sessions/6d290df9-cc9e-4703-bcc4-2143eba007aa]]) — the latter also showing that packets nest, since a resumed session's first prompt is itself the previous packet. A third hop later that night ([[sessions/019fb0c0-23aa-7583-9035-ad2d71dd4ac6]], claude-code → codex again) exercised the byte budget on real data: the packet dropped 14 older events with the designed "omitted to fit" note and the named digest path, and the receiving codex session completed the pending wiki commit (`147ed73`) without re-asking the user. A fourth hop ([[sessions/019fb0d1-0ea2-71c3-a0c2-616d5973374c]], claude-code → codex) rescued another deferred wiki commit (`4d9171a`) and closed with a "what did we do?" recall question answered write-free. In hindsight, those auto-continued commits were acting on `@subagent-stop` internal notes the user never wrote — the behavior the ask-first rework replaced ([[gotchas/subagent-stop-promoted-to-user-request]]).

**Ask-first packet** (commit `6414c80`, 2026-07-30, [[sessions/e112664f-9954-4d8e-8fd2-a11e13d66bc0]]): the packet stopped telling the receiving agent to continue on its own. Three changes in `buildHandoff`: the "Last reported state" lead now always prefers the last main `@stop`, falling back to a `@subagent-stop` line only when the chain holds no `@stop` at all — and then labeled "internal subagent note — not a user request"; the footer replaced "Continue the work from exactly where the session stopped" with an instruction to not start working yet, report the current state in 1-3 lines, and wait for the user's go-ahead, noting that `@subagent-stop` lines are internal subagent notes; and the header ground rule closes with "report it briefly, and wait for the user's go-ahead" instead of "then continue the work". `memoria_recall` shares the lead selection, so the fix covers recall output too. The motivating incident — a packet promoted a subagent's "commit the wiki changes too" annotation to authoritative state and codex spent five minutes executing it — is [[gotchas/subagent-stop-promoted-to-user-request]]. Tests: the packet test replays the incident's exact tail (`@stop` → `@subagent-stop` → `@session-end reason: prompt_input_exit`), and `TestRunHandoffLeadSubagentFallback` covers the labeled fallback.

**How run resolves sessions**: `.memoria/sessions.md` is an append-only index — one `RFC3339 - SID - NAME` line per session, written by `indexSession` in `cmd/hook.go` with per-sid dedup. NAME starts as the first user prompt collapsed to 80 chars; for claude-code sessions, capture rewrites it in place with the live session title on every `stop`/`session-end` (commit `c2e7e3a`, mechanics in [[concepts/session-capture]]), so the picker, `--session` name matching and the MCP default all show real titles — codex sessions keep the first-prompt name. Recency is positional: last line = newest; the `date` field is parsed but never sorted on. `findDigest` maps a sid to its digest file, preferring `pending/` over `processed/` and taking the highest incarnation ([[gotchas/implicit-session-end]]); `digestClient` reads the digest's `client:` frontmatter to choose native resume vs handoff. The MCP `memoria_digest` and `memoria_recall` defaults ("newest session") ride the same `readSessions` helper via the shared `resolveSession` — changes there touch both the CLI and MCP paths.

**Interactive selection** lives in `cmd/tui.go` on Bubble Tea (`charmbracelet/bubbletea` v1.3.10 with bubbles + lipgloss): `selectOption(title, opts)` renders an arrow/j-k list (enter selects, esc aborts); `isTTY()` is a stubable var so tests can force either path. The CLI itself is framework-free: manual switch dispatch in `main.go` plus one stdlib FlagSet per subcommand.

**`memoria search [--trash] <text | #tag>`** (commit fca4954) finds wiki pages by content substring or frontmatter tag and prints the chosen one, using the same `selectOption` picker when several match; trashed pages stay hidden unless `--trash`.
